# ProxyIdentityHeaderTrust

版本：0.1.1。作者：dhtfish98。

这是一个仅在 `127.0.0.1` 运行的认证代理身份头边界实验。它针对“后端直接信任 HTTP 客户端提供的身份头”这一授权失效模式，提供可重复的弱基线与修复对照。源码位于 [src](../src)，测试与弱强对照位于 [tests](../tests)。源码独立编写；不包含上游程序代码、外部身份资料或真实凭据。

## 实验边界

实验有四个本机服务实例：合成身份发行者、弱基线后端、修复版后端、认证代理。发行者保存不透明的短期测试令牌，并提供受代理凭据保护的 `/introspect`；它还提供只供说明的发现端点。代理只接受单一 Bearer 令牌，在本地向发行者查询身份，然后**新建**发往后端的请求头：`X-Lab-Identity`、`X-Lab-Role` 和短期、路由绑定、一次性签名断言。它不转发客户端提供的身份、转发来源或代理认证头。修复版后端验证断言及身份头一致性，再按角色授权；直连、重复头、篡改、重放和错误路由均被拒绝。

对照结果：客户端直连弱后端并自填 `X-Lab-Role: admin` 可访问 `/admin`；同请求直连修复版后端被拒绝。经过代理的普通用户夹带伪造管理员头仍被拒绝，代理签发的管理员身份可通过。测试还覆盖头部大小写、下划线别名、重复 `Authorization`、重复断言、签名重放、失效断言及错误发行者凭据。非 ASCII 的代理凭据或后端身份头会得到明确的 401 或 403 响应，不会让请求处理线程因比较函数异常而中断。

0.1.1 补丁在包元数据中记录已核实的 GitHub 作者邮箱，并让本地发行者拒绝同时出现 `Transfer-Encoding` 和 `Content-Length` 的请求。v0.1.0 标签与 Release 保持为历史记录。

此实验的发行者仅模仿 OIDC 相关身份查询的输入输出，**不是完整 OIDC 实现**。其 `issue()` 测试夹具直接创建假身份令牌，没有授权码、PKCE、浏览器会话、发现/JWKS 验证或真实用户登录流程。生产系统需要成熟的 OIDC 验证组件、受保护的代理至后端网络或双向 TLS、正确的反向代理拓扑、密钥轮换及跨实例重放状态。本实验的签名断言只在单进程本机后端共享状态的条件下展示信任边界，不能作为生产身份协议直接使用。

## 已知限制

实验只接受固定的 `GET /whoami` 与 `GET /admin`，只使用合成角色 `viewer` / `admin`，并且只绑定 IPv4 环回地址。未实证真实 OIDC 提供者、容器/负载均衡拓扑、跨主机传输、分布式重放防御、性能上限或 CVP 申请结果。合成基线与工程测试不能代替申请人的真实合法用途和相应平台验证。
